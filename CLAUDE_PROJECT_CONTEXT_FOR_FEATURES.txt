SwiftPharma project context for Claude

Use this as the full product and codebase context when proposing or implementing new features.

Project summary
SwiftPharma is a full-stack online pharmacy and medicine delivery platform for the Indian market. It is built around fast delivery, verified medicines, prescription-based access control, AI-assisted prescription handling, admin review flows, and a modern mobile-first shopping experience.

The app is not just a storefront. It includes:
- A consumer shopping flow for OTC and prescription medicines
- Prescription upload, OCR, AI parsing, and pharmacist/admin review
- Order management with delivery tracking
- Medicine reminders and refill subscriptions
- AI health assistant and drug interaction tools
- Admin analytics and operations dashboards
- Delivery dashboard and order tracking support

Tech stack

Prescription and RX features
- Users can upload prescriptions
- OCR extracts text from uploaded prescription images
- AI parsing is used to interpret medicines and dosage details when available
- There is fallback logic when Gemini is unavailable or rate-limited
- Prescription status is tracked across pending, review, approved, rejected, expired, and related lifecycle states
- RX-gated products require approved prescriptions before purchase or subscription
- Admin prescription queues support approve and reject flows
- Prescription lifecycle utilities exist to keep pending or expired states consistent over time
- Expired or review-window logic is handled in backend utilities and scripts

Medicine reminder features
- Users can create reminders for medicines
- Reminder entries support dose logs
- Reminder frequencies include daily, twice daily, three times, weekly, and custom
- Reminder schedules support specific times and days of week
- Reminder stats can be generated for adherence and streaks
- Reminder reminders are route-protected and tied to the authenticated user

Subscription features
- Users can create recurring medicine subscriptions
- Subscriptions are linked to a product and user
- Frequency options include weekly, biweekly, monthly, and bimonthly
- RX-restricted products require an approved prescription before subscription creation
- Users can pause, resume, cancel, and update subscriptions
- A background scheduler processes due refills
- Reminder notifications for upcoming refill dates are generated by a scheduled job
- Refill processing can create auto-refill orders

Order and delivery tracking features
- Orders are listed for customers and admins
- Order detail pages and tracking pages exist
- Delivery dashboard exists for delivery users
- Tracking utilities generate current location, destination, and ETA data
- A tracking simulator advances active deliveries in development or when enabled
- Tracking state includes event history and live map support
- Order status transitions use canonical delivery statuses such as pending, confirmed, processing, out_for_delivery, delivered, and cancelled

AI and assistant features
- AI health assistant page exists for general medical guidance
- Prescription scanning uses OCR plus AI-assisted parsing
- Drug interaction checking route exists
- Drug information route exists

- Medical MCP initialization is part of server startup

Project conventions and implementation notes
- Keep features aligned with the existing route structure and protected route patterns
- Preserve current auth and role-based access control behavior
- Reuse existing services, route modules, and controllers where possible
- Prefer backend utilities for lifecycle or schedule logic instead of duplicating logic in pages
- Preserve prescription validation and review gating for RX products
- Keep admin actions separate from customer actions
- Be careful with scheduled jobs so they do not duplicate work or create repeated notifications
- Keep tracking logic deterministic enough for development and testing
- Avoid introducing breaking API changes unless the UI and backend are updated together

Operational notes
- The app has both frontend build artifacts and backend runtime utilities in the workspace
- Some generated log files may contain sensitive runtime output and should not be reused in prompts
- The root package uses npm workspaces
- The server entry loads environment variables before importing app modules
